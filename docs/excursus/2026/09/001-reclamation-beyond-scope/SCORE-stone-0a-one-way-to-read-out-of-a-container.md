### What the one function owns, and why

```
(defenum :c::Read   :Elem [tget]  :At [d]  :AtReg [r d]  :Reg [r])
(defn :c::read-out [t <- String  rd <- :c::Read  o <- Out  a  pg] -> Out
  (let [lo (match rd ...the load, per kind...)]
    (cond ((ptr-ty? t)  (emit lo (count-hex t)))
          ((word-ty? t) lo)
          (:else (fail "a read out of a container, of unknown type " t)))))
```

**It owns the EMISSION of every read (the inline load, or the call) and the count on what comes
back in rax.** It does not own the runtime's load. The `nth` trie arm loads inside `tget`, which
this compiler never sees, so a function that owned "load + count" would have to fake that load.
It does not need to: the count goes on the *answer*, after the array arm and the call have joined
in rax, and that is where stone 0 already put it. So `:Elem` carries `tget`'s address, and
`read-out` emits the whole dispatch: `cmp [rax-16],0 ; jne ; mov rax,[rax+rcx*8+8] ; jmp ; call
tget`. The site no longer spells any of it.

**The kinds are load shapes, not verbs.** The field accessor's general arm and the `match`
payload share `:At`. A site now says only *what* it read (`t`) and *how the load is spelled* (a
`Read`). Neither decides whether to count. `:c::count-read` is gone
(`grep -c count-read elf/compile.wat` = 0).

**`word-ty?` is a positive list, not `(not ptr-ty?)`:** `i64`, `bool`, `nil`, `enum:*`, `fn:*`.
A type in neither list is unknown, and that is the `:else` → `:c::fail`.

### Two behaviour changes, both refusals, neither an emission

1. **`nth` accepts only a Vector.** At HEAD it also took a `rec:` operand, through a bare-load
   arm, and typed the answer `i64` (`elem-ty` of a non-`vec:` falls back to `"i64"`). That is a
   default for an element type nothing declares, and an `i64` is never counted: STOP-3's shape.
   It also accepted `str`, which went through the Vector dispatch. I removed the record arm. The
   read now requires a declared element type:

   ```

          "#wat.runtime/TypeMismatch {:message \":wat::core::nth: expected Vector, PersistentVector, List,
   ```

## Row 3 — ⛔ the rung reached · **CHECK**

**What is structural (the construction):**

- A site cannot spell a counted read without saying the type. `t` is a positional argument of
  the only function that emits these loads. There is no "skip" path: `ptr-ty?` counts,
  `word-ty?` does not, and anything else is `:c::fail`.
- Every load shape is a `:c::Read` variant, and `read-out`'s `match` has no `_`. The interpreter
  refuses a non-exhaustive match. I measured this on a scratch program: *"non-exhaustive: enum
  :t::R missing arm(s) for variant(s): B"*, exit 3. So a new variant without its load arm does
  not reach bootstrap stage 0. And whichever arm it gets, the count is applied after the `match`,
  so it is counted.

**What is a check (`tools/reads.sh`, run first by `tools/elf-run.sh`):**

1. Every heap-load spelling in `compile.wat` (`:c::load-at`, `:c::mov-rm`, `:c::movzb`, a raw
   `"4[89cd]8b…"`, a memory `0fb6`) is inside `read-out`, or is one of six named exceptions,
   **each with a count**. The exceptions are: `peek` and `length` (`"488b00"` ×2, i64); `wait`
   (stack, not heap); `code-point-at` ×2 (a byte); the tier-3 `match` tag (`(:c::load-at 8)`,
   slot 0, i64); and the `scalar-bytes` prologue. The prologue is the one real container load
   outside the function: the register *is* the field, and every use is counted by `:Reg`.
   Because each exception has a count, a new read that reuses an allowed spelling still fails.
2. Every runtime entry `(:c::at-NAME rt)` is classified. `tget` may appear only as
   `(:c::Read.X {:f (:c::at-tget rt)})`. **An unclassified entry fails.** That is the map `get`
   case: its routine will be new, so the check stops whoever adds it and names `:c::read-out`.
3. `read-out` still contains `(:c::count-hex t)`, and `count-hex` has exactly two callers
   (`share`, `read-out`).

The check fails on a bypass. Mutations were applied to scratch copies of the final
`compile.wat`:

```
== field-bypass        (the accessor's general arm spelled as stone 0 had it, count forgotten)
```

The first version of the check let `tget-direct` through: it accepted any line that mentioned
`:c::Read.`. I tightened it to require the entry *as a field of* a `Read` constructor before any
run of it on the tree.

**Why not UNREPRESENTABLE, and what that would take.** `:c::emit` takes any hex, `:c::call`
takes any address, and a record's fields can be read with its accessor anywhere. wat has no
module privacy and no opaque types, so nothing in the dialect can stop a function from emitting
a load or calling `tget` without mentioning `read-out`. The check's own holes are the same holes
seen from outside. It reads spellings, so a load built from a new hex prefix, or a runtime
address reached some way other than `(:c::at-X rt)` (for example `(nth rt 22)`), gets past it.
So does a person who deliberately classifies `mget` as NOTREAD. The top rung would need one of
two things:

- **Privacy:** `:c::emit`/`:c::call` visible only to a lower layer, which exposes typed emitters
  (`read-out`, `store`, …) and no raw hex. That is a language feature (module-private
  definitions) plus a split of `compile.wat` along it.
- **A typed layout:** `elf/lib/runtime.wat`'s entries that answer held values return a
  `:c::ReadEntry` rather than an `i64`, and `:c::call` refuses anything but a plain `i64`. That
  closes only the runtime-call half, needs `runtime.wat` (out of scope here), and still depends on
  nobody unwrapping the record by hand. That makes it a stronger convention, not
  unrepresentability.

## What surprised me

1. **`nth` on a record was a divergence at HEAD.** It is not F-188's kind: the native binary
   answers `7` where the interpreter raises a run-time TypeMismatch. The contract closed it as a
   side effect, because its element type was a default.
2. **The interpreter's exhaustiveness check is the strongest structure available.** It turns
   "every load kind is counted" into a bootstrap-stage-0 refusal, with no tooling. It cannot see a
   verb that never builds a `Read`, and the check exists for exactly that gap.
3. **My first check had a hole**, and a mutation found it before the tree saw it: `tget-direct`
   passed because the line merely mentioned `:c::Read.`.

### The check, tested adversarially

- **A new site loading through `:c::mov-rm`** — a spelling none of the strike's five mutations used
  — **is caught** (exit 1).
- **A load placed AFTER another instruction in the same hex literal is NOT caught** (exit 0):
  `(:c::emit o "4889c1488b4108")`, which is `mov rcx,rax ; mov rax,[rcx+8]`. The load regex
  anchors on a literal's opening quote (`"4[89cd]8b`), so it sees only a literal's FIRST
  instruction. The strike named this class in general ("`:c::emit` takes any hex"); this is the
  concrete shape. **A cheap tightening exists:** scan every byte-aligned pair inside every hex
  literal for a REX prefix (`48`/`49`/`4c`/`4d`) followed by `8b`, not just the first pair. It does
  not reach the top rung — a load can still be spelled another way — but it closes the easiest
  route into the gap. Recorded here, not done: it is the strike's tool and the next stone that
  touches it should take it.
- `slot`, classified NOTREAD, is `slot_set` — it answers a COPY of the container. Correct.
