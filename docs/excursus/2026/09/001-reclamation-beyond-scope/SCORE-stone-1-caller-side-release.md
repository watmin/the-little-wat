## Row 6 — ⛔ STOP-1 is answered · **SPLIT: proved for symbols, REPRODUCED OPEN for borrows**

### The half that is proved, with the citation

**The share count and the arm word are the SAME WORD.** That is the whole answer and it is not
written down anywhere in the tree:

- `:c::heap-arm` is `1` — `elf/lib/runtime.wat:1701`, *"the word every allocation writes at its
  start, one word BEFORE the pointer it hands out."*
- path 3's gate is `flat-test (:c::cmp-mi (:c::rax) (:wat::core::- 0 w) (:c::heap-arm))` —
  `elf/lib/runtime.wat:632`, i.e. `cmp qword [rax-8], 1`, and the `jne` that follows
  (`:c::rt-branch (:c::negate-cc (:c::cc-zero)) (:c::at-vconj lay)`) sends a mismatch to the
  **copying** `vec_conj`.
- `:c::share` emits `488378f800 740448ff40f8` = `cmpq [rax-8],0 ; je +4 ; incq [rax-8]` —
  `elf/compile.wat:3053`. **The same address.** A shared Vector's word reads 2, not 1.
- path 2 is closed by the same increment: `:c::arm-own` is `4294967297` = `0x1_00000001`
  (`elf/lib/runtime.wat:1705`) and `own-test` compares for equality (`:629`).
- `vec_conj_own` is emitted *only* when the container is a symbol that is a parameter of the
  enclosing function — `elf/compile.wat:1890` (`own?` = Symbol AND `:c::linear?`), and
  `:c::Prog/linear` is built by `:c::linear-of` over the parameter vector `pv`
  (`elf/compile.wat:2858`). So the value a callee may extend in place is always **something a
  caller passed as an argument**.
- every user call shares its pointer-typed **symbol** arguments: `:c::push-args`
  (`elf/compile.wat:3954`) and `:c::arg-into`/`:c::arg-shares?` (`elf/compile.wat:3917`).

So for a symbol argument, path 3 is closed before the callee is entered. Probed, with the heap
churned hard after the release so anything wrongly freed is overwritten:

```
stop1: agree   [99|240000|3|10|20|30]
```

(`user/bump` conjs its linear `v` and returns i64; `main` then allocates 20,000 vectors and
reads `base` back: length still 3, elements still 10/20/30.)

### The half that is NOT closed — and it is REPRODUCED, not feared

`:c::share` fires on a **symbol** only (`elf/compile.wat:3033`: `(and (= (kindv a pg) Symbol)
(ptr-ty? ...))`). A pointer that reaches a call as a *borrowed element read* — `(user/f
(wat.core/nth g 3))` — is never incremented, keeps arm word 1, and if it is also the youngest
allocation, **path 3 fires on a vector the caller still holds.**

The probe, run against both compilers, same source, same box:

```
borrow2-BASELINE: DIVERGE  native=[30|240000|4|1|99] (exit 0)   interp=[30|240000|3|1|30] (exit 0)
borrow2-MINE:     DIVERGE  native=[30|240000|4|1|0]  (exit 0)   interp=[30|240000|3|1|30] (exit 0)
```

Read the last two fields. The interpreter says the borrowed row is **3 long and ends in 30**.

- **At HEAD, today, with no change at all:** length **4**, last element **99**. The in-place
  extension is already observable through the caller's container. That is a silent wrong answer
  and it is **pre-existing** — the F-168/F-170/F-180 class, found here by accident.
- **With the caller-side release:** length **4**, last element **0**. The rewind freed the
  extension word and 20,000 later allocations overwrote it.

**So the stone does not create this hazard; it converts it from a wrong length into a read of
reclaimed memory.** C-120's statement release has the same exposure one level down — the probe
shape works there too — but the caller-side release widens it from discarded statements to every
qualifying call.

`elf/compile.wat:1890` is where a guard would go (require `(:c::ronly? ...)`-style freshness of a
non-symbol container argument, or share borrowed pointers). **I did not write it — STOP-4.**
A guard invented to make this go away is the patch, not the stone.

The probes are on disk: `elf/probe/callrel-stop1.wat` (the symbol argument, must agree) and
`elf/probe/callrel-borrow.wat` (the borrowed argument, diverges at HEAD and here).
`tools/probe.sh` runs each in about 90 s.

### Two defects in the delivered work

1. **§7 of `tools/mem.sh` prints a measurement it did not take.** *"It is FLAT in n: 960 KiB at 1e6, 964 at 2e6, 972 at 3e6"* is a hardcoded `echo`. §7 checks that `escape` AGREES; nothing checks that it is FLAT. If the release regressed and `escape` leaked again, §7 would still print "FLAT" and `mem: ok`. That is the failure this excursus's EXPECTATIONS opened by warning against. The fix is a real gate: at the committed n = 200,000 the two hypotheses predict ~1 MB (released) against ~13.7 MB (leaking), so a threshold between them discriminates.
2. **`:c::allocates?` does not exist.** The report says *"gate on `(:c::allocates? …)`, the call graph is already there"* — the call graph is (`Prog/fns`, the `pokers` fixpoint); the predicate is new work, not a reuse. Named so the next brief does not treat it as present.

A smaller one: `elf/probe/callrel-borrow.wat:34` comments `;; 99` on a line that correctly prints `30`.

### Why stone 1 does not land on main yet — the four questions

- **Honest? NO.** It widens a known silent wrong answer (F-188) into a read of freed memory. Landing it with F-188 open ships the worse failure mode on purpose.
- **Done is done? NO.** fib32 pays +9.86% for a release that has nothing to free — fib allocates nothing. The `allocates?` gate is what makes the stone's cost match its benefit, so it belongs INSIDE stone 1, not after it.

So: stone 1 is preserved on branch `excursus-001-stone-1`, pushed. Stone 0 fixes F-188 on main first. Stone 1 then takes the `allocates?` gate and a real §7 gate, is rebased onto stone 0, and must show `callrel-borrow` AGREEING before it merges.
