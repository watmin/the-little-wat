### One defect in the delivered code — fail-open polarity

The `match` site resolves the field type as `(if (< fi (length ftys)) (nth ftys fi) "i64")`. An
index it cannot resolve becomes `i64`, and **an `i64` emits no count** — so the unknown case takes
the UNSAFE branch. F-168's polarity rule is that an unknown must disable the optimisation, and
here the optimisation is *not counting*. It is almost certainly unreachable; if it is ever reached
it re-opens a door silently. It should be `:c::fail`. Carried into stone 0b by name.

### What stone 0b starts from

The shadowdancer's ablation is the map: the cost is the **guard, not the increment** (a NOP in
place of `incq` costs +11.081% against +11.082%), split **`nth` ~5.2 points, field reads ~5.6,
`match` ~0**, and dropping either large site re-opens its doors. So narrowing is closed as an
option, and three mechanisms stay open, none measured:

1. **count at the STORE, not the read** — in read-dense code a value enters a container far less
   often than it is read out. Unmeasured; that ratio is the first thing to establish.
2. **a cheaper guard** — the `cmp [rax-8],0 ; je` exists because a String LITERAL has count 0 in a
   read-only segment. If a Vector or record can never be such a literal, those types need only
   `incq`. That premise is unverified and is a STOP trigger, not an assumption.
3. **count only types that can reach an own path** — whole-program, since the compiler sees every
   function: a type no linear parameter is ever extended through needs no count.

`elf/src/borrowed.wat` is the oracle for all three: any mechanism that lets one of its seven marked
lines diverge is a narrowing in disguise.
