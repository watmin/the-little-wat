# elf/probe -- shapes that broke the compiler, kept so they cannot break it again

These are not part of the compiled corpus (`elf/src`, `elf/bad`, `elf/bench`, `elf/native`).
They are small programs that once miscompiled, run with `tools/probe.sh`, which compiles one
of them and diffs the native answer against the interpreter's in about three seconds.

    tools/probe.sh elf/probe/f168-and-tail.wat

| probe | what it pins |
|---|---|
| `f168-and-tail.wat` | a self tail call as the last operand of an `and`. Before C-196 the generator compiled it as a loop while `:c::tail-self?` answered false, and the loop never ended. |
| `f168-and-tail-vec.wat` | the same shape reading a vector. **This one did not crash** -- it exited 0 and printed `false\|false` where the interpreter prints `true\|false`. A silently wrong answer is the reason this directory exists. |
| `share-shadow.wat` | two `let` bindings of the same name, each passed to a mutating callee. A share-set keyed on the NAME elides the second, so the inner value keeps its owned marker and is mutated in place -- native `"z2!z1!z2!"` against the interpreter's `"z2z1!z2!"`. Pins that the key must be the BINDING (C-210). |
| `share-join.wat` | a share inside one arm of an `if`, then another after the merge. Carrying the set past the join elides a share the other path still needs -- native `"z1!-z1!"` against `"z1-z1!"` on the false path. Pins that `:c::patch` must clear it (C-210). |
| `nested-vec.wat` | a `(Vector :- [(Vector :- [i64])])`, built with `conj` and read with nested `nth`. Pins the fact that nested containers DO compile -- F-171 claimed they did not, and used that to justify a design decision (C-199). |
| `regabi.wat` | every shape the per-function register convention has to get right at once: arity 1, 2 and 3 leaves; a call-free leaf with a self tail call, whose back edge must write rdi and rsi rather than rbx and r12; a leaf whose arguments are not in parameter order, which must stay on the stack path; a String parameter, which has to be SHARED in rax before it is placed; a call site whose argument is itself a call, which forces the push-and-pop-into-registers path; and a function whose ADDRESS is taken, which must keep the stack convention because `call *rax` cannot know an arity. |
| `f170-cond-test.wat` | a write site inside a `cond` clause's TEST, with the clause body reading the name afterwards. `:c::live-after` walked kids from index 1 -- right for `(f a b)`, wrong for `(test body)` -- so the write looked dead and was done in place. Native printed 4, the interpreter 3. |
| `callrel-borrow.wat` | **F-188 door 1, diverges at HEAD.** The pointer reaches the callee as `(nth g 3)` -- not a symbol, so `:c::share` never increments it -- and `vec_conj_own` extends a live container's element in place. The interpreter says the row is 3 long and ends in 30; HEAD says 4, ending in `99` -- and with excursus 001 stone 1's caller-side release, `0`, because the rewind frees the extension the length still counts. |
| `own-shadow.wat` | **F-188 door 2, diverges at HEAD, and no borrowed pointer crosses any call.** `(let [v (nth g 3)] (conj v 99))` inside a function whose PARAMETER is also `v`: `own?` keys `linear?` on the name, so the shadowing binding inherits the parameter's ownership. Interpreter `30 3 30`, HEAD `30 4 99`. It is what proved sharing at the call site would be a stem. |
| `str-borrow.wat` | **F-188's String form, door 1, diverges at HEAD.** A fresh String read out of a Vector by `nth` and passed to a function that `concat`s onto its linear parameter. `str_cat_own` tests the same count word `vec_conj_own` does, so the caller's element became `"ab1!"`. `:c::fresh-str?` closed the non-symbol OPERAND of a concat; it never saw a borrowed String reach a linear symbol. |
| `str-shadow.wat` | the String form, door 2: `(let [s (nth g 3)] (concat s "!"))` where the parameter is also `s`. Interpreter `4 "ab1" 3`, HEAD `4 "ab1!" 4`. |
| `field-borrow.wat` | F-188 through the RECORD FIELD read site, door 1, both a direct accessor and a record parameter used through one field only. The field's Vector came from `vec_conj_own`'s copying path, so it carries the owned arm and path 2 -- not path 3 -- writes in place. Interpreter `5 5 4`, HEAD `5 6 5`. |
| `field-shadow.wat` | the record field read site, door 2. Interpreter `5 4`, HEAD `5 5`. |
| `match-shadow.wat` | F-188 through the `match` PAYLOAD binding of a tier-3 enum: `{:xs xs}` shadows the linear parameter `xs`. Interpreter `5 4`, HEAD `5 5`. Door 1 cannot reach this site -- the bound name is a Symbol, and passing it on shares it. |
| `tier1-borrow.wat` | a tier-1 enum read out of a Vector by `nth` and matched: the payload IS the subject, so this is closed by the `nth` count, not a fourth site. Interpreter `4 3`, HEAD `4 4`. |
| `count-bare.wat` | **stone 0b's premise, as a program.** Reads an EMPTY Vector, a record, and a record's Vector field out of containers, then touches each. If a non-string pointer type can be a read-only count-0 literal, a bare `incq [rax-8]` faults here first. Agrees today: `1\|0\|1\|0\|"t"\|3`. |
| `count-literal.wat` | **stone 0b's guards that must SURVIVE.** A String LITERAL (count 0, read-only) read out of a Vector, a record field and a `penum:` whose payload is a String, each passed to an in-place `concat`; and UNIT variants of a `penum:` over a Vector and of a `henum:` read out of Vectors and matched. Agrees: `4\|3\|"cde"\|4\|3\|0\|-1\|2\|0\|7\|2`. Each guard removed in turn -- the literal guard from every type, the literal guard from `penum:` alone (guarding it by tier, not payload), the tag guard -- segfaults it. |
| `count-trie.wat` | **stone 0b's trap door 2**: the bare `incq` on what `tget` answers. Rows read out of a 40-element (trie) Vector -- flat, empty, a trie row, and an `arm-own` row with room in its block -- each handed to an in-place `conj`. Agrees after stone 0b; before stone 0 (`dada88f`) the trie row and the `arm-own` row both come back one too long. |
| `check-param-shadow.wat` | **F-190.** A `let` re-binding a PARAMETER at a new type: the interpreter's checker REJECTS it (blaming a `:wat::core::vec` that is not in the program), while re-binding a `let` name at a new type is accepted. The native compiler runs it and prints `4`. |
| `let-shadow-crash.wat` | **F-191, a valid program the native compiler SEGFAULTS on.** `(let [y "abc"] (+ (let [y 1] y) (length y)))`: interpreter `4`, native SIGSEGV. Mechanism not established; two hypotheses refuted -- see F-191's matrix. |
| `nth-record.wat` | **closed by stone 0a.** `nth` on a RECORD: HEAD's compiler had an arm for it whose answer typed as a default `"i64"` and was never counted, and the native binary printed `7` where the interpreter raises `TypeMismatch ... expected Vector`. Stone 0a's required type makes it a compile refusal: `nth: operand is not a Vector`. |
| `match-i64.wat` | **F-195, closed by excursus 002 stone 4.** A Vector bound from a `match` was typed by the waist's `(:else "i64")`, so it was never shared, and a callee `conj`'ing its linear parameter grew the caller's live vector in place: native `4\|5`, interpreter `4\|4`. `match` now has an arm (the join of its arms, each typed with its pattern's bindings); the binary gains the 11-byte share and agrees. |
| `inline-origin.wat` | **excursus 002 stone 4: an inlined call is typed as the call.** `user/none`'s body is a unit variant of a generic enum, which fixes nothing about `T`; inlined, the argument was typed from that body -- `(:user::Opt)` against the parameter's `(:user::Opt :- [i64])`, one boundary and two type conflicts. The inliner's `let` now carries the callee's declared return (`:c::mknode-ty`), the same type the call has when it is not inlined. Agrees `none` both ways; the gates show 0. |
| `generic-bare-share.wat`, `generic-bare-tier.wat` | **found by excursus 002 stone 4: two silent wrong answers on `main`.** A generic enum written as a bare parameter type, `(o :- :user::Opt)`, fixes no `T`; the language infers it per call. `:c::variant-ftys` answered `"i64"` for the uninstantiated `:T`, so the callee was compiled for `T = i64`: a Vector payload was never shared (`-share`: interpreter `44`, HEAD printed a pointer), and a String payload -- tier 1, the pointer itself -- was matched as tier 3 (`-tier`: interpreter `1\|0`, HEAD `4197723\|0`). Both exit 0. Now a compile refusal: *cannot type a generic enum with no type argument*. |
| `variant-param.wat` | **excursus 002 stone 5: a variant is a type.** A parameter typed `(:user::Opt.Some :- [String])` accepts only a `Some`, and is itself an `Opt` -- passed on to a function that wants the parent. HEAD refused the variant type (*a type form this compiler does not know*). Agrees `3\|3\|0`; the boundary gate counts the three variant-to-enum arguments as `variant`, not conflicts. |
| `variant-param-wrong.wat` | **stone 5, the other half of Liskov.** A `None` where a `Some` is wanted. `wat --check` refuses it; the native compiler refuses it too, naming the call: *cannot pass argument 0 of user/needs-some: it wants (:user::Opt.Some :- [:wat::core::String]) and is given (:user::Opt.None :- [:?])*. `elf/refuse-variant.wat` keeps the refusal checked on every `elf-run`. |
| `generic-unit-unfixed.wat` | **D9, closed by stone 5.** A unit variant of a generic enum passed where nothing but the parameter fixes `T`. It always ran correctly (a unit variant is its tag in every tier), but was typed `henum::user::Opt` against the parameter's `penum::user::Opt;str`, so both gates failed it. Its `T` is now free until the parameter fixes it: the argument is `(:user::Opt.None :- [:wat::core::String])`, as the checker says, and both gates pass. |
